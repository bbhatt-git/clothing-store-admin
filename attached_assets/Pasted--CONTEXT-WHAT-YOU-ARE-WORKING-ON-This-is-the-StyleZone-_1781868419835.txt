## CONTEXT & WHAT YOU ARE WORKING ON

This is the **StyleZone Admin Dashboard** — a WooCommerce admin panel for a clothing store.

**Repo:** `https://github.com/bbhatt-git/clothing-store-admin`

Current stack (READ CAREFULLY — this shapes every decision below):
- pnpm workspaces, Node 24, TypeScript 5.9
- **Frontend: React + Vite** (`artifacts/woo-admin/`) — wouter, TanStack Query, Recharts, shadcn/ui, next-themes
- **API: Express 5** (`artifacts/api-server/`) — WooCommerce REST API SDK, JWT auth
- Styling: Tailwind CSS, dark-first (charcoal/near-black + orange accent), no emojis
- Build: esbuild, Orval codegen from OpenAPI spec

**Problem:** The store frontend was partially Next.js and the admin is Vite — they are split. Deployment to Vercel or Cloudflare fails or produces partial results.

### 5. BULK PRODUCT IMPORT / EXPORT

Add a dedicated page at `/products/import-export` accessible from the Products page header via an "Import / Export" button.

#### IMPORT — CSV Upload

**CSV column spec (create a downloadable template):**
```
id (optional, if provided = update existing),name,sku,description,short_description,
regular_price,sale_price,status,stock_quantity,manage_stock,stock_status,
categories (comma-separated slugs),tags (comma-separated),images (comma-separated URLs),
weight,length,width,height,attributes (JSON string)
```

**Import flow UI:**
1. Upload zone (drag-and-drop + click-to-browse, accepts `.csv` only)
2. After file selected: parse CSV client-side, show **preview table** of first 5 rows with column mapping
3. Column mapping step: dropdowns to map CSV columns → product fields (in case column names differ)
4. Validation step: show a count of valid rows, list of rows with errors (row number + what's wrong), and let user choose: skip errors or abort
5. "Start Import" button → progress bar with live count (e.g. "Importing 34 / 150 products...")
6. When done: summary toast + downloadable error report CSV if any rows failed

**API route (`/api/products/import`):**
- Accept multipart/form-data with the CSV file
- Process in batches of 20 (configurable)
- For each row: validate required fields → call WooCommerce REST API
- Return a streaming response or polling endpoint for progress
- Return a final summary: `{ success: number, failed: number, errors: Array<{row, error}> }`

#### EXPORT — CSV / JSON

**Export flow UI:**
1. "Export Products" button opens a dialog
2. Options:
   - **Format**: CSV or JSON
   - **Filter**: All products / By category / By status (published, draft, out of stock)
   - **Columns to include**: checklist of all available fields (preselected: name, SKU, price, stock, status)
   - **Include variations**: toggle (creates child rows for variable products)
3. "Export" button → spinner → downloads file automatically
4. File name: `stylezone-products-{YYYY-MM-DD}.csv`

**API route (`/api/products/export`):**
- Accept query params: `format`, `category`, `status`, `fields`, `include_variations`
- Fetch all matching products from WooCommerce (paginate through all pages)
- Serialize to CSV or JSON
- Return as file download with correct Content-Disposition headers

### 7. UI INCONSISTENCIES TO FIX

Fix all of these precisely:

- **Loading flicker**: any component that renders empty/null for even 1 frame before data loads must be replaced with its skeleton variant
- **Table pagination**: must show "Showing X–Y of Z results" text, working prev/next buttons, page size selector (10/25/50/100), and the pagination must not reset scroll position
- **Form inputs**: all inputs must have consistent 36px height, visible focus ring in `--accent` color, proper `name` attribute for accessibility
- **Button hierarchy**: only one primary (orange fill) button per toolbar. Secondary actions use ghost or outline variant. Destructive actions (delete) use `variant="destructive"` (red)
- **Status badges**: use consistent pill shape (border-radius 9999px), 6px horizontal padding, 4px vertical. Colors:
  - published/active/approved/completed → green
  - draft/pending/on-hold → yellow/amber
  - trash/cancelled/rejected → red
  - processing → blue/indigo
- **Dropdown menus**: row action menus (edit, delete, etc.) must use a `DropdownMenu` trigger, not bare buttons spread across the row
- **Mobile responsiveness**: sidebar must collapse to a drawer on screens < 768px. Use `Sheet` from shadcn for the mobile sidebar. Page titles must truncate on small screens.
- **Search bars**: all search inputs must debounce (300ms) so they don't trigger an API call on every keystroke
- **Number formatting**: all prices must show with currency symbol (format: `$1,234.00`). Stock numbers use `toLocaleString()`. Order IDs formatted as `#12345`.
- **Date formatting**: consistent across the app — use `Intl.DateTimeFormat` with the locale-aware format: `Jun 19, 2026` (not ISO strings in the UI)
- **Confirm delete**: all delete actions must show a confirmation dialog with the item name clearly stated. Never inline delete without confirmation.
- **Toast stacking**: max 3 toasts visible at once, newest on top
